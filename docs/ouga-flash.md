## 原版入口与操作方式

1. 打开「秋白工作室 → 欧加线刷」。重复点击激活已有窗口，不创建第二个刷写任务窗口。
2. 在右侧「刷写设置」切换「全量包模式 / 售后包模式」；两个页面分别保留已加载的目录、分区选择及选项。
3. 「快捷云提取」接受完整包直链或本地 payload.bin 路径。快捷方案与原版一致：boot、init_boot、高通修复 FastbootD 关键分区、联发科修复 FastbootD 关键分区、云解包方案。也可编辑输入分区名。点击「提取分区」选择独立输出位置；云解包方案提取全部，不出现额外品牌选择界面。
4. 全量页「刷写文件」可选择本地 Payload.bin / ZIP，或解包好的镜像文件夹；点击「解包Payload」提取全部。售后页选择散包文件夹。支持拖入目录、镜像和本地 Payload；拖入或选包只准备文件，不操作手机。ZIP 解压、Payload 提取完成后重新扫描和校验。
5. 分区表保持原版四列：勾选、名称、大小、文件路径。名称与大小只读，文件路径可编辑；替换路径重新校验，失败保留原有效映像。展开大小和 SHA-256 放在提示信息中，不额外添加表列。表头可全选 / 取消选择。
6. 选择原版操作选项，然后点击「开始线刷」。程序内部依次准备文件、发现并读取设备、必要时提示准备模式切换、生成计划、最终确认、执行。多设备必须明确选择，AB 必须选择最终启动槽；缺少必要附加镜像时弹出文件选择。没有独立「读取设备」「生成计划」按钮。
7. 最终确认列明序列号、平台、槽位、源文件到真实目标的映射，以及切槽、删除逻辑分区、擦除 Super、清除数据等不可逆步骤。确认前不开始刷写。

「清除数据」「自动重启」默认选中；全量包的「分区表校验（实验性功能）」默认开启，售后页保持原版禁用状态。关闭整包校验不关闭所选镜像有效性、真实目标、容量、解锁、平台、槽位及重复目标的底线检查。

「修复FastbootD」是独立操作，不继承清除数据和自动重启系统，完成后停留在 FastbootD。「停止操作」按命令边界停止：等待当前写入结束，不启动下一步。空闲点击只记录无可停止任务，不启动命令，也不能回滚已写内容。

## 刷写模式

| 模式 | 核心顺序 |
| --- | --- |
| 全量普通（AB / 强力 / 仅 FBD 均不勾选） | FastbootD 读取设备表和处理实际 COW；普通分区当前槽、无槽一次。高通有槽 modem 转普通 Fastboot 分别写 A/B，再按需回 FastbootD 收尾；MTK 在 FastbootD 处理。 |
| AB 通刷 | 物理有槽 A/B、无槽一次，逻辑分区只写最终目标槽。仅换槽时切槽、删除计划涉及的双槽逻辑分区并重建目标槽；高通 modem 普通 Fastboot 双槽。 |
| 强力线刷 | 固定目标 A。起始 B 先处理 COW、预写 A 槽非逻辑且非 modem 分区；预写全部成功才切 A 和重建。起始 A 走直接重建分支。随后附加镜像、其余分区和平台对应的 modem 阶段。 |
| 仅 FBD | 只接受已在 FastbootD 的高通设备，目标为另一槽。确认、倒计时后切槽、双槽删除 / 目标槽重建、COW 和刷写；过程中不返回普通 Fastboot。最终按选项决定是否重启系统。 |
| 修复 FastbootD | 普通 Fastboot 下检查平台关键镜像完整性，再按真实有槽 / 无槽表写入。高通九类，MTK 八类（含 lk，不含 modem / recovery）。成功后进入 FastbootD 并检查稳定连接，不擦数据、不重启系统。 |
| 售后 FB 模式 | 校验已有或自动提示生成 Super；普通 Fastboot 擦除 / 刷 Super，保留 120 秒等待，重新探测并确认后续计划。关键分区双槽、FastbootD 剩余阶段；已合入 Super 的分区不重复刷。读取双槽逻辑容量后选较大槽，相等选 A，读取失败停止。 |
| 售后 FBD 模式 | 独立售后计划：COW、当前槽普通分区、平台对应的 modem 双槽阶段及收尾。不把名称仅包含 modem 的任意映像当作 modem。 |

AB、强力、仅 FBD 必须具有匹配的 my_company / my_preload。来自包或刷写准备阶段用户明确指定；不使用 SMT 临时目录、内置替代品或自动制造空映像。各刷写模式勾选项保持原版互斥，并允许全部取消。

所有目标解析自真实设备分区表，不简单给全部名称追加 _a / _b。逻辑分类来自设备查询与 SMT 明确集合，不把全部 my_* 无限扩大为可删除分区。Super 后重探测；目标或启动槽变化时再次确认，不静默改变执行计划。数据清除仅在前序全部成功后执行，保留高通 / MTK 对 userdata、metadata 和 -w 的差异，不包含 FRP / misc。

## 工具与包准备

复用应用内 payload；欧加优先使用 qiubai/bin 内随应用提供的 7-Zip、lpmake 和完整 platform-tools。资源提取保留子目录，不覆盖旧功能在 qiubai 根目录使用的 adb/fastboot。原版页面没有新增工具配置入口；用户已配置路径仍优先，缺失时通过文件选择配置，使用应用 QSettings 的 Ouga 分组持久保存。

- 应用组织名为 QiuBai，应用名为 Orange Tools；Windows 默认设置位于 HKCU\Software\QiuBai\Orange Tools\Ouga。工具键为 adb、fastboot、payload、7z、lpmake，ROM 服务键为 rom。ROM 服务地址默认为空，不预填作者地址。
- 高通清除数据在首次写入前检查 fastboot 同目录的 mke2fs.exe、make_f2fs.exe、mke2fs.conf。缺失时提示选择可信完整 platform-tools；仍缺失则阻止。文件存在检查不是签名或版本一致性认证。
- 已提供 7-Zip 26.03 命令行及格式库、Google platform-tools 37.0.1 完整 Windows 包、用户 SMT 参考包内的 lpmake；不进行系统安装。qiubai/bin/README.md 与 manifest.json 保留版本、来源、许可及逐文件摘要。lpmake 为参考包的未签名二进制，构建版本未知，不能声称已验证其上游构建来源。缺失工具仍只阻止相应解压 / Super 生成。
- lpmake --help 正常输出完整 AOSP 用法而退出 1 时，只将该能力查询视为有效；Super 生成及设备命令的非零退出、异常退出、FAILED/错误输出仍立即失败。USB 驱动及 ROM 服务地址不由放置这些文件完成。
- 支持普通镜像目录、售后 IMAGES/RADIO 与可确定映像的 my_* 子目录。多候选、重复目标、冲突映射阻止；任意 bin、说明文件或包内脚本不作为分区。
- rawprogram 只作受校验的完整映像映射资料；多段拼接、非零文件偏移等不支持格式明确停止，不执行其中的擦除或偏移写入。
- 镜像检查可读性、Sparse 头 / 块边界、展开大小、路径边界和 SHA-256；执行前与每次写入前再核对文件未变化。
- Payload 使用现有工具列出并提取全部或指定分区；核对大小和可用摘要，再重新扫描。增量包缺少匹配旧镜像或不可验证的清单时停止。输出为用户选择的源目录以外独立空目录。
- Super 支持 SMT 实际 super_def 的设备、分组、分区、路径和容量；仅支持经过校验的单物理设备布局。Sparse 转换、填充与对齐在独立工作副本完成，不给源映像补零、不修改源 JSON。缺图、容量不足、冲突或不支持 LP 布局停止，不制造空内容。
- 解压前先列出并验证路径、链接、Windows 特殊名、重复路径与冲突；禁止输出越界。解压后重新校验，不删除原包。

## 云下载与自动救砖

手动下载链接从原版「快捷云提取」输入框进入，不新增下载页或摘要输入框。Qt Network 下载支持取消，以及有有效验证信息的断点续传；检查 Range / Content-Range、验证器、长度和服务提供的校验值。无可信摘要时不把长度验证当作固件真实性认证。

下载使用 .part / .resume.json，成功才更名。失败、取消或校验不符保留文件，不覆盖已有完整包，也不自动删包。失效断点要求另选保存名；返回整包的 200 响应不拼接旧断点。跨来源重定向不转发认证请求头，日志不暴露 URL 凭证或原始请求头。

ROM 服务适配 SMT 的 /series、/devices、/versions（GET）与 /download-link（POST）响应格式。列表 Items 兼容字符串和 Name 对象；链接读取 Links 与 RequestHeaders，字段大小写不敏感。服务须由用户配置和另行验证，测试仅访问本机模拟服务。

售后页勾选原版「自动救砖模式」后点击「开始线刷」，进入原版 30 个一加机型 / 版本选择流程（无新增搜索框），随后下载、解压、加载售后包并准备计划。缺少 ROM 服务时明确提示不可用，不默认访问 SMT 作者服务；缺少 Super / 工具时停在准备阶段。**向手机写入前仍需最终确认**，不扩展到 EDL / BROM / 绕过解锁。

## 设备互斥、日志与 ARB

- 应用内操作租约覆盖欧加与已有设备操作；旧任务未结束时不接管。持有租约暂停冲突轮询，结束恢复监控。
- 单设备命令全部以 -s 绑定序列号；模式切换只等原设备，不接管另一台手机。模式等待上限 120 秒，30 秒窗口内连续三次一致快照才视为稳定。
- QProcess 直接传程序路径和参数，不拼接 shell。非零退出、异常退出或明确 FAILED 输出停止后续步骤；删除逻辑分区仅明确「不存在」可继续，传输错误不忽略。
- 停止不杀正在刷写的进程。无响应显示人工处理提示；只读查询有独立超时，不套用到 flash / erase / reboot。对话框内停止并返回也不能恢复旧任务。
- 活跃任务禁止关闭欧加窗口、所属菜单或退出程序，允许最小化。已写内容不回滚；失败后不继续擦数据 / 重启。操作系统强制退出、断电或拔线不在程序保护范围内。
- 界面日志保留原版时间戳与灰 / 红 / 橙 / 绿 / 蓝颜色。计划、原生命令输出及结果独立保存到 Qt AppLocalDataLocation 的 ouga-logs，实际路径在日志显示；分享前注意序列号和路径隐私。
- 进度按实际刷写次数统计，双槽计两次；无法可靠获取字节进度时只显示阶段，不伪造速度或成功。最终结果保存成功后才显示全部完成。

「ARB熔断检测」解析 xbl_config ELF64/OEM 元数据。用户可提供可信当前镜像，或在已有 ADB 授权和读取权限下回读当前槽，不调用 su、不主动提权或解锁。只有可信基准存在才比较，降级风险阻止；无基准显示未验证。

**镜像 ARB 索引不等于完整硬件熔断状态，也不能保证整包不存在其他反回滚风险。** 未发现索引降低不代表绝对安全。

## 代码结构与参考优化

本轮不增加按钮、选项或刷写模式，保持原有界面布局。参考源码只作为流程资料，不执行其中的命令，也不照搬失败后继续刷写的行为。

- `ougaflashwindow.cpp` 负责控件、布局和进度；`ougaflashworkflow.cpp` 负责包准备、设备发现与任务衔接；`ougaflashdialogs.cpp` 负责确认、ARB 和救砖选择。私有控件工厂与进度封装共享，不复制样式实现。
- 分区归一化、真实目标解析、逻辑分类、关键镜像集合、附加镜像需求及设备快照比较集中在 `ougaflashtypes`。快捷提取、修复和售后计划使用同一关键镜像集合。删除无消费者的包模式、ARB 输入和分区计数草稿字段。
- 纯计划生成器共享单目标、双槽、镜像列表及关键镜像步骤。强力 B 槽物理预刷只安排一次；MTK modem 延后但不离开 FastbootD；售后关键镜像和已合入 Super 的镜像不进入重复刷写尾部。输入顺序变化不会改变小镜像优先的确定性顺序，双槽次数和总大小按实际命令计算并检查溢出。
- 执行器共享异步复检和确认后的恢复入口。稳定快照包含 has-slot 属性，每次写入前仍核对镜像摘要；无安全保证的摘要缓存不引入。格式化依赖统一校验，并在首次写入前再次检查。
- 命令的流式输出和结束返回使用同一原始输出记录，避免重复记日志。最终日志或结果持久化失败不报告成功，不显示全部完成。
