## 原版入口与操作方式

1. 打开「秋白工作室 → 欧加线刷」。重复点击激活已有窗口，不创建第二个刷写任务窗口。
2. 在右侧「刷写设置」切换「全量包模式 / 售后包模式」；两个页面分别保留已加载的目录、分区选择及选项。
3. 「快捷云提取」接受完整包直链或本地 payload.bin 路径。快捷方案与原版一致：boot、init_boot、高通修复 FastbootD 关键分区、联发科修复 FastbootD 关键分区、云解包方案。也可编辑输入分区名。点击「提取分区」选择独立输出位置；云解包方案提取全部，不出现额外品牌选择界面。
4. 全量页「刷写文件」可选择本地 Payload.bin / ZIP，或解包好的镜像文件夹；点击「解包Payload」提取全部。售后页选择散包文件夹。支持拖入目录、镜像和本地 Payload；拖入或选包只准备文件，不操作手机。ZIP 解压、Payload 提取完成后重新扫描和校验。
5. 分区表保持原版四列：勾选、名称、大小、文件路径。名称与大小只读，文件路径可编辑；替换路径重新校验，失败保留原有效映像。展开大小和 SHA-256 放在提示信息中，不额外添加表列。表头可全选 / 取消选择。
6. 选择原版操作选项，然后点击「开始线刷」。程序内部依次准备文件、发现并读取设备、必要时提示准备模式切换、生成计划、最终确认、执行。多设备必须明确选择，AB 必须选择最终启动槽；缺少必要附加镜像时弹出文件选择。没有独立「读取设备」「生成计划」按钮。
7. 最终确认列明序列号、平台、槽位、源文件到真实目标的映射，以及切槽、删除逻辑分区、擦除 Super、清除数据等不可逆步骤。确认前不开始刷写。

「清除数据」「自动重启」默认选中；全量包的「分区表校验（实验性功能）」默认开启，售后页保持原版禁用状态。关闭整包校验不关闭所选镜像有效性、真实目标、容量、解锁、平台、槽位及重复目标的底线检查。

「修复FastbootD」是独立操作，不继承清除数据和自动重启系统，完成后停留在 FastbootD。「停止操作」按命令边界停止：等待当前写入结束，不启动下一步。空闲点击只记录无可停止任务，不启动命令，也不能回滚已写内容。

## 刷写模式

| 模式 | 核心顺序 |
| --- | --- |
| 全量普通（AB / 强力 / 仅 FBD 均不勾选） | FastbootD 读取设备表和处理实际 COW；普通分区当前槽、无槽一次。高通有槽 modem 转普通 Fastboot 分别写 A/B，再按需回 FastbootD 收尾；MTK 在 FastbootD 处理。 |
| AB 通刷 | 先清理 COW，保持原活动槽完成物理有槽 A/B、无槽一次；这些写入全部成功后，仅换槽时切槽、删除计划涉及的双槽逻辑分区并重建目标槽。随后附加镜像及逻辑分区只写最终目标槽。有槽 modem 最后双槽刷写：高通转普通 Fastboot，MTK 留在 FastbootD；无槽 modem 随物理分区只写一次。 |
| 强力线刷 | 固定目标 A。起始 B 先处理 COW、预写 A 槽非逻辑且非 modem 分区；预写全部成功才切 A 和重建。起始 A 走直接重建分支。随后附加镜像、其余分区和平台对应的 modem 阶段。 |
| 仅 FBD | 只接受已在 FastbootD 的高通设备，目标为另一槽。确认、倒计时后切槽、双槽删除 / 目标槽重建、COW 和刷写；过程中不返回普通 Fastboot。最终按选项决定是否重启系统。 |
| 修复 FastbootD | 普通 Fastboot 下检查平台关键镜像完整性，再按真实有槽 / 无槽表写入。高通九类，MTK 八类（含 lk，不含 modem / recovery）。成功后进入 FastbootD 并检查稳定连接，不擦数据、不重启系统。 |
| 售后 FB 模式 | 校验已有或自动提示生成 Super；普通 Fastboot 擦除 / 刷 Super，保留 120 秒等待，重新探测并确认后续计划。关键分区按参考平台顺序逐分区 A/B；进入 FastbootD 后，剩余物理有槽分区 A/B、无槽一次，按镜像大小排序，已合入 Super 的分区不重复刷。预检计算较大逻辑容量槽（相等 A）；全部写入成功后重新读取稳定设备表并核对该选择，最后设置启动槽，再按选项清数据 / 重启。任何必要容量未知、设备表或预览槽位变化均停止。 |
| 售后 FBD 模式 | 独立售后计划：COW、当前槽普通分区、平台对应的 modem 双槽阶段及收尾。不把名称仅包含 modem 的任意映像当作 modem。 |

AB、强力、仅 FBD 必须具有匹配的 my_company / my_preload。来自包或刷写准备阶段用户明确指定；不使用 SMT 临时目录、内置替代品或自动制造空映像。各刷写模式勾选项保持原版互斥，并允许全部取消。

所有目标解析自真实设备分区表，不简单给全部名称追加 _a / _b。逻辑分类来自设备查询与 SMT 明确集合，不把全部 my_* 无限扩大为可删除分区。Super 后重探测；目标或启动槽变化时再次确认，不静默改变执行计划。数据清除仅在前序全部成功后执行，保留高通 / MTK 对 userdata、metadata 和 -w 的差异，不包含 FRP / misc。

复用应用内 payload；欧加和其他设备操作共用 qiubai 根目录的 adb/fastboot、配套 DLL 及格式化辅助工具，统一来自同一份 platform-tools 37.0.1。qiubai/bin 仅提供 7-Zip 和 lpmake；资源提取保留这两个工具的子目录，不再嵌入或提取 bin/platform-tools 的重复副本。原版页面没有新增工具配置入口；用户已配置路径仍优先，缺失时通过文件选择配置，使用应用 QSettings 的 Ouga 分组持久保存。

- 应用组织名为 QiuBai，应用名为 Orange Tools；Windows 默认设置位于 HKCU\Software\QiuBai\Orange Tools\Ouga。工具键为 adb、fastboot、payload、7z、lpmake，ROM 服务键为 rom。ROM 服务地址默认为空，不预填作者地址。
- 高通清除数据在首次写入前检查 fastboot 同目录的 mke2fs.exe、make_f2fs.exe、mke2fs.conf。缺失时提示选择可信完整 platform-tools；仍缺失则阻止。文件存在检查不是签名或版本一致性认证。
- 已提供 7-Zip 26.03 命令行及格式库、Google platform-tools 37.0.1 完整 Windows 包、用户 SMT 参考包内的 lpmake；不进行系统安装。qiubai/bin/README.md 与 manifest.json 保留版本、来源、许可及逐文件摘要。lpmake 为参考包的未签名二进制，构建版本未知，不能声称已验证其上游构建来源。缺失工具仍只阻止相应解压 / Super 生成。
- lpmake --help 正常输出完整 AOSP 用法而退出 1 时，只将该能力查询视为有效；Super 生成及设备命令的非零退出、异常退出、FAILED/错误输出仍立即失败。USB 驱动及 ROM 服务地址不由放置这些文件完成。
- 支持普通镜像目录、售后 IMAGES/RADIO 与可确定映像的 my_* 子目录；自动加载 `.img`、`.raw`、`.sparse`（扩展名不区分大小写），均经过相同的内容、展开大小和摘要校验。拖入这些镜像时加载所在目录，仅准备文件、不写入手机。多候选、重复目标、冲突映射阻止；`.bin` 仍须通过受校验的 rawprogram 确定用途，任意 bin、Payload、说明文件或包内脚本不作为分区。
- rawprogram 只作受校验的完整映像映射资料；多段拼接、非零文件偏移等不支持格式明确停止，不执行其中的擦除或偏移写入。
- 镜像检查可读性、Sparse 头 / 块边界、展开大小、路径边界和 SHA-256；执行前与每次写入前再核对文件未变化。
- 选择已解包文件夹时与参考版一致只枚举并做结构检查（大小、Sparse、映射、super），不计算 SHA-256；开始刷写时仅对所选镜像以 idealThreadCount 个 worker 并行计算摘要并核对大小未变，再生成计划。执行前复检与每次写入前摘要核对保持不变。
- Payload 优先在应用内提取全部或指定分区（见下文“解包性能与校验边界”），其余情况使用现有工具；核对大小和可用摘要，再重新扫描。增量包缺少匹配旧镜像或不可验证的清单时停止。输出为用户选择的源目录以外独立空目录。
- 「解包Payload」优先使用所选目录下的 images（直接选择 images 时不再追加）。已有文件、隐藏文件或未完成镜像时，在同一级使用 images-随机标识 的独立新目录，并在日志显示实际路径；连续解包仍使用同级目录，不向上次结果内嵌套，不覆盖或删除已有输出。目录检查在后台执行；底层仍校验来源隔离、链接、空目录和创建结果，碰撞时失败而不是覆盖。此调整只作用于完整解包，快捷提取仍要求独立空目录。
- Super 支持 SMT 实际 super_def 的设备、分组、分区、路径和容量；仅支持经过校验的单物理设备布局。Sparse 转换、填充与对齐在独立工作副本完成，不给源映像补零、不修改源 JSON。缺图、容量不足、冲突或不支持 LP 布局停止，不制造空内容。
- 解压前先列出并验证路径、链接、Windows 特殊名、重复路径与冲突；禁止输出越界。解压后重新校验，不删除原包。
- ZIP 解压进度读取 7-Zip 的实时百分比，支持输出分片、回车及退格更新；进度只递增，普通日志与终端进度分流。工具报告 100% 时仍等待退出与输出校验，全部通过才显示解压完成；失败或取消不显示 100%。进入 Payload 提取时重新归零，通过隐藏的 Windows 伪终端读取现有 payload.exe 的真实完成操作数 / 总操作数，按已选择分区汇总显示“解包中 N%”（解包Payload）或“提取中 N%”（快捷提取），不以时间或文件大小模拟进度。工具计数须与 manifest 对应，校验完成前最高 99%；仅在退出正常、镜像长度 / SHA-256 及重新扫描全部通过后显示 100%。分区日志为“[提取] 名称.img... OK”，每个 OK 必须通过该镜像校验；失败与取消不伪报成功。Windows 不支持伪终端时明确报错，不静默退回无进度提取。ZIP 仅解压唯一 payload.bin，保留整包路径校验；正常日志不输出 7z 清单、启动横幅和终端控制字符，失败时保留诊断。

### 解包性能与校验边界

- 与 VioletToolBox 的 PayloadProcessing 一致，全量 Payload 在应用内提取（src/services/ougapayloadextractor.cpp）：分区依次处理，单个分区内的操作按逻辑处理器数并行，每个操作解码前核对 data_sha256_hash，写入按块随机定位；进度按已写入字节计算，校验完成前最高 99%。ZIP 中以存储方式保存的唯一 payload.bin 直接在原包内按偏移读取，不预解压；压缩、加密、重复或结构异常的条目仍走上述 7z 只解 payload.bin 的流程。
- 仅当所选分区全部为带数据摘要的 REPLACE / REPLACE_BZ / REPLACE_XZ / ZSTD / ZERO / DISCARD，且目标区段无缺口、无重叠地恰好覆盖整个镜像时才走应用内提取；增量包或任何不满足这些校验条件的情况继续使用 payload.exe（2–8 个 worker），流程及校验不变。参考实现对差分包直接报错，这里保留原有能力。
- 应用内提取先校验各操作数据，全部写入结束并关闭写入句柄后，再以 1 MiB 固定缓冲完整读取 .partial，核对实际长度及最终镜像 SHA-256。只有与 manifest 一致才发布 .img、标记该分区 OK；扫描复用本次已验证摘要，不再重复哈希。Windows 优先使用 CNG；流式计算失败时从文件开头重新使用 Qt SHA-256，不接受部分摘要。该最终落盘校验是本项目保留的完整性保护，不宣称参考版具有相同校验时机。刷写前及每次写入前仍完整复检。失败或取消时尝试删除本次创建的 .partial（包括预分配失败），保留已完成镜像及原有文件。
- 每次提取使用专属、可复用的低优先级 Qt 线程池，不再为每个分区反复创建和销毁线程；每个工作任务复用输入缓冲和 XZ / ZSTD 解码器。Windows 逐操作 SHA-256 使用系统 CNG 的可复用校验器，初始化或计算失败则完整回退到 Qt SHA-256；XZ 仍检查压缩流校验、完整输入消耗及精确输出长度。
- ZIP 定位、Payload manifest 解析、操作范围检查与输出目录检查在后台运行，GUI 只接收进度和结果。解析期间停止会等待后台工作返回后结束任务，窗口不可提前销毁；不更改全局线程池或界面线程优先级。
- ZSTD（操作类型 14）与 VioletToolBox 的 `Type.Zstd` 对齐，使用固定版本 1.5.7 的上游单文件解码器静态编入程序，不要求选择额外 exe，不增加运行时 DLL。每个工作线程复用解码上下文；检查帧、窗口上限、字典标识、完整输入消耗及精确输出长度，拒绝尾随 / 拼接帧和越界数据。发布时附带 `licenses/zstd-BSD.txt`；来源及重生成步骤记录在 `third_party/zstd/README.md`。
- xz（静态链接）与 bzip2 取自 Qt MinGW 套件的 mingw64/opt（ougacodecs.pri，可用 OUGA_CODEC_ROOT 覆盖）；deploy.ps1 将 libbz2-1.dll 一并部署并列为必需文件（可用 -CodecBinPath 指定）。 CNG 来自 Windows 系统 bcrypt，不新增分发 DLL。
- 提取后的扫描使用独立、最多 2 线程的校验池，按确定顺序返回结果。扫描取得的 SHA-256 仅在同一次准备任务内用于 manifest 比对，不重复完整读取可刷写镜像；被排除的镜像仍单独核对 manifest。
- 不持久缓存摘要，不以文件大小或修改时间代替刷写前的完整复检。长度、Sparse、路径、映射、manifest 与失败阻止规则保留。ZIP 仍只提取经列表校验的唯一 payload.bin，不执行整包解压。
- 实际收益取决于 CPU、磁盘与固件压缩方式；性能测试应使用同一真实 Payload、独立输出目录，并对比全部输出镜像的大小和 SHA-256。模拟测试通过不代表真机兼容性验证。

**历史性能记录说明：** 下列测时对应各段所述的旧实现，并非补入最终落盘摘要校验后的性能数据。当前版本新增一次有界流式读取，尚未用同一真实大包重新测速；不能沿用旧耗时宣称当前速度或已经追平参考程序。

2026-10-04 本机实测：对同一 8,997,436,618 字节的真实 Payload 分别执行旧版和新版准备流程（提取及完整校验，不含 ZIP 预解压），从 474.411 秒降至 251.596 秒，耗时减少 46.97%。65 个输出镜像合计 12,049,133,568 字节，逐项大小及 SHA-256 完全一致；本机 8 个逻辑处理器，新版使用 8 个 worker。该结果为旧版先、新版后的单轮 SSD 测试，可能受系统缓存影响，不代表所有包或磁盘均有相同收益，也未与 VioletToolBox 可执行程序进行同机测速。
